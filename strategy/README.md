固定提交：`904b6f59b98a6cfd77b4ae26f72f2746e4a97025`，读取日期 2026-10-21。原始 Skill、策略参考、卡牌/遗物标签和样例快照保存在 `upstream/`，文件 SHA-256 见 `SOURCE.json`。不运行仓库脚本，不自动追踪远端更新。

实际生效的适配层在 `../lib/strategy.mjs`：每次请求先发送通用的卡组短板、准备度和未来 3～5 层路线评估流程，再根据地图、选牌、商店、篝火或事件加载相应策略摘要。避免每次发送整个仓库带来额外用量与延迟。新建议和历史记录中的 `strategy` 字段保存来源与固定提交。

保留的核心判断包括：输出足够后补防御和运转、比较加入卡牌的稀释代价、仅在游戏允许时把跳过作为正式候选、以资源与后续补给判断精英路线、比较删牌/药水/补短板购买与留钱、用实际升级前后效果权衡休息和锻造。

适配优先级：当前实机效果和合法选项 > 用户的辅助建议范围及现有 JSON 输出 > 外部策略经验。只提供建议，操作由玩家完成。原文分值和血量阈值是启发，不能冒充校准过的战力、战损或胜率；原文冲突的绝对阈值不机械执行。不使用 proposals 假设，也不把卡名标签当成当前版本的卡牌效果。部分上游条目带有未经实机核对的机制标签，因此卡牌与遗物标签仅保留用于审阅，没有无条件注入模型。

原始样例属于策略推理样例；本项目自动化测试验证参考确实进入 AI 请求、场景分流、来源可追溯以及非法建议仍被拒绝，不代表已经实测模型胜率或行为质量。事件按用户当前可用选项及通用资源原则适配，上游并无独立事件规则文件。
